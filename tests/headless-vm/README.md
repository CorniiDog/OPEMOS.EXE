# Headless VM harness

Run `npm run test:vm-headless` from the repository root. The harness boots the existing immutable x86_64 Fedora appliance through QEMU TCG, creates a disposable qcow2 system overlay and a 64 MiB synthetic raw disk, and controls the guest only through NoCloud seed media and the serial console.

Run `npm run test:vm-lifecycle` for the slower destructive-to-runtime regression matrix. It sends SIGTERM at seed creation, active QEMU, and result publication; replaces a live runtime directory; forces a guest timeout; and then proves a clean same-state recovery run. All targets remain disposable harness-owned paths.

The VM has no emulated network device, GUI, monitor, SSH workflow, host-disk passthrough, secrets, or persistent host permission. Guest code refuses the root disk and a second wrong-serial fixture, then authorizes only the uniquely serialed synthetic virtio disk at the exact image/device capacity boundary. Its test-only helper boundary binds protocol version, request and intent tokens, expiry, image hash/size, canonical/raw node, capacity, identity token, and independent authentication/authorization flags; spoofed protocol, device, expiry, and authentication cases fail before opening the disk. It reports bounded block-copy progress over serial, exercises mid-copy cancellation plus synthetic-media sanitization, performs a complete copy and SHA-256 readback, then creates unambiguous synthetic `rootfs-A` and `rootfs-B` partitions, mutates only B, restores B from a disposable backup, and verifies the rollback hash. Finally, it executes the exact installation-media helper from the read-only seed against a sparse, uniquely identified 16 GiB virtio disk and proves that the recovery/root and undersized fixtures remain excluded. The large fixture is sparse and is never opened for writing. Every runtime artifact is created beneath the nested ignored `work/` directory and removed on exit.

The VM protocol fixture does not stand in for macOS code signing or privileged-service authorization. Production physical writing remains disabled until a separately signed, installed, least-privilege helper can be authenticated against an approved executable hash, signing identity, version, and protocol. Installation review and sacrificial physical-media validation remain irreducible external boundaries.

The final machine-readable record is atomically written to `tests/headless-vm/results/latest.json`; stale prior results are never accepted. Runtime/result roots and their immediate directories must be real non-symlink directories. Missing QEMU, seed-media tooling, or the base image produces a `skipped` record and exit status 2; test failures produce a `failed` record and exit status 1. The timeout is restricted to 30-900 seconds, and signal/abort cleanup terminates QEMU, removes the runtime overlay and disks, and records failure.

Set `STEAMOS_HEADLESS_VM_BASE` only when the immutable appliance lives outside `builder/appliance/fedora-builder-x86_64.qcow2`. The value must name a regular, non-symlink qcow2 file. Homebrew's QEMU UEFI firmware is discovered automatically; a non-Homebrew installation can set `STEAMOS_HEADLESS_VM_FIRMWARE_DIR` to the directory containing `edk2-x86_64-code.fd` and `edk2-i386-vars.fd`. `STEAMOS_HEADLESS_VM_TIMEOUT_SECONDS` may reduce or extend the default 180-second deadline.

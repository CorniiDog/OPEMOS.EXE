# Automatic OMEN Robot execution

`omen-robot.yml` executes on completion of **01 Windows EXE**, **02 Ubuntu
AppImage** and **03 macOS Executable** on protected Main. Manual Main dispatch
is an additional route. There is no privileged PR or producer-artifact code
execution. A hosted guard verifies the live protected source and Root's fresh
180-second runner heartbeat. The external fixed runner job guard independently
checks the exact workflow, repository, event and Main before checkout. A missing
runner fails quickly with an artifact showing all twenty unavailable entries.

The dedicated runner executes Robot Framework **7.5**, official wheel SHA-256
`5a194db36524604fafa1da89adebc837db9a95adf15ffd746e09ce98251e6c68`.
Root installs the runtime, registered runner/service, job guard, profile and fixed
planner; this source change performs none of those operations. The workflow
uses no new secret, SSH key, token distribution or endpoint. The heartbeat
variable is `OPEMOS_OMEN_ROBOT_RUNNER_STATE`; readiness is route availability,
never VM, GUI or GPU admission.

## Executing graph

`inventory.robot` has twenty explicit inventory tests and three independent
platform tests. Each test obtains a fresh, pinned, owner-reviewed ordinary
queue manifest from the fixed installed planner, consumes normal successful
submission, then joins the **existing** worker. No replacement worker starts.
An absent macOS producer does not suppress available Windows or Ubuntu tests.
Every exact artifact enumerated for a platform gets its own bound result; one
artifact cannot cover another. Platform enumerations must include all current
expected producer artifacts. Missing roles/artifacts fail, never skip.

The adapter consumes the existing CI11 source/descriptor reader, complete-byte
canonical queue metadata path, role, package, pointer, storage, wrong-readiness,
virtualUSB, installed SteamOS, GPU and closure validators. Those files are copied
byte-identically. Historical CI11 results remain historical; the Robot adapter
has not yet run. Current-head canonical qualification must be supplied through
the existing source-bound contract, never by relabeling the old receipt.

Graphical `imaging_host` and `steamos_target` roles use `guest.robot` with the
actual existing driver APIs: Windows `connect`/`pointer`, Ubuntu `transact`.
The driver checks actual QMP destination, PID/birth/socket/argv/disk, admitted
app/window/session and freshly acquired frame before absolute movement and
mouse-down/up. Four output descriptors are reserved before input. Its finite
child/raw-stream/EOF/reap evidence is retained. `Assert Current Observed Result`
requires a separate current native/console observer result with the same
fresh action/runtime/nonce; the complete independent native/frame evidence is
then verified again by the final receipt validator. Merely labeling a PNG or
asserting `native_observer=true` cannot satisfy that final validator. Non-GUI
Fedora/nested roles use `role.robot` and their own exact boot/kernel identity;
they do not pretend to have a GUI. VirtualUSB is an owned material graph member,
not an invented replacement OS VM. All twenty catalog identities stay unchanged.

The Mac native sender/current package is an owning EXE dependency. This adapter
refuses a missing Mac sender, and never invents a Mac VM on non-Apple OMEN.
The Mac imaging application must run on its admitted real Apple Silicon lane;
its distinct x86 SteamOS output/install target remains on OMEN.

For each executable, the existing transaction validator requires exact producer
workflow/run/attempt/artifact/package/binary bytes, genuine GUI output image and
manifest, owned virtualUSB write/flush/**full readback**, separate installed
SteamOS target and boot, then same-target old/new kernel NVIDIA loaded/render
and normal plus abrupt-power recovery evidence. An independently admitted
shared-GPU lease, exact four-function restoration and closure are mandatory.
No physical USB, native installation or new hardware admission is granted.

## Installation ABI and artifacts

`ci/robot-installed-hook-contract.json` is the complete fixed planner ABI. Root
must materialize real current package/input, driver/observer, original/runtime,
resource, queue/admission and generated result operands. These are executable
normal transactions, not past manual receipts. The fixed planner's `collect`
operation is read-only and may export only explicitly public current evidence.
Private configs/fixtures/credentials and original or raw image disks are never
GitHub artifact inputs. No arbitrary command or source comes from dispatch/PR
inputs. Additional build/heal manifests must be a complete admitted normal
graph with exact dependencies and fresh generated output custody; absence is a
concrete affected-case failure, not permission to reuse old acceptance.

The same dedicated stage owns new CI copies, exact **14,400-second** eligibility,
UID/type/full9/marker/path checks and normal queue/active-lock checks. Unknown or
active closure prevents expiry. Originals, old failures, old job/lease records
and unrelated source/user/release data stay outside cleanup. Full 60-billion-byte
VM accounting, one 32-GiB RAM/swap-zero/CPU0-9 pool including overhead, existing
heavy admission and GPU serialization remain normal queue requirements. The
fixed runner installation must use the existing admitted operational resource
route; it must not hold an incompatible controller lock while waiting on that
same worker. No alternative worker or resource bypass is implemented here.

`run_omen_robot_guest.py` writes actual `output.xml`, `report.html`, `log.html`,
`xunit.xml` and the source/run/attempt/nonce-bound numeric result from that
execution. Host Robot reports and reviewed current screenshots, argv, raw
logs, and NVIDIA loaded/render/restoration evidence upload with `if: always()`.
Failure collection retains the first error and separately records collection
failure or unknown closure. GitHub errors/summary and red Robot cases notify
verified deviations. No pipeline/all20/fullstack pass is claimed by source or
runner availability.

## Exact review and deployment sequence

1. Root and owning EXE review the entire new source graph and normal hook/profile
   integration, then Core reviews the exact imaging-sensitive PR/base/head.
2. On an already admitted OMEN guest/CI lane, batch the unchanged CI11 public,
   private and required canonical qualification with the **new**
   `tests/test_omen_robot.py` cases. Preserve all old results. No controller
   project execution is required or authorized by this handoff.
3. Root installs the official runtime/fixed guard/planner/profile, normal guest
   job source and existing driver/observer copies, registers only the dedicated
   runner, and verifies the heartbeat using the existing approved route.
4. After reviewed source publication, a protected producer completion executes:

   ```sh
   "$OPEMOS_ROBOT_PYTHON" -m robot --outputdir robot-results \
     --output output.xml --report report.html --log log.html --xunit xunit.xml \
     tests/robot/inventory.robot
   ```

   Inside each exact admitted case, the ordinary queued step invokes:

   ```sh
   "$OPEMOS_ROBOT_PYTHON" scripts/run_omen_robot_guest.py \
     identity.json IDENTITY_SHA tests/robot/guest.robot FRESH_OUTPUT_DIRECTORY
   ```

   `role.robot` replaces `guest.robot` only for the declared non-GUI role.
   Every actual missing operand remains failed and concrete in the uploaded
   results. Genuine current Mac and GPU operands can be completed independently.
